API Fragment Pattern

Send form data to a backend and show the result

This demo shows a very common builder action: the user submits a form, HyperBricks forwards that data to a backend-style endpoint, and the page shows the returned result. The route also sends a small HTMX event so other parts of the screen can refresh after the save.

What is simplified in this demo

Instead of calling a real external service, this page uses two local mock endpoints. One answers like a successful save, and the other answers like a conflict. That keeps the example easy to run while still showing the real route shape.

Successful save

This form simulates a save that succeeds and returns a friendly confirmation panel.

Save with conflict

This one sends the same kind of data, but the backend answer says the change cannot be applied.

Submit either form and the rendered result will appear here.

Refresh probe

This panel reloads on page load and also after a successful or failed save. It shows how one save action can tell other parts of the page to update too.

How the form fields are reshaped

The browser fields on this page do not have to match the backend field names. HyperBricks can rename and reorder them before sending the request.

{"p_project_slug":"$project","p_file_id":$file_id,"p_kind":"$kind","p_path":"$path","p_content":"$content"}
