Builder Boundary Pattern

Plugin vs API Route Split

This page compares two common ways to handle a user action in HyperBricks. The left side is a thin route that forwards form data to an API-like endpoint and renders the response. The right side uses a plugin because the request needs extra thinking first: validation, cleanup, and a small execution plan before anything is shown back to the user.

API Fragment

Simple save or rename action

Think of this as a normal form submission where the browser sends fields, HyperBricks reshapes them for the backend, and the backend answers with structured data. That is a good fit for <API_FRAGMENT_RENDER>.

Same action, different backend answer

Here the request shape stays the same, but the backend returns a conflict message instead of a success row. The route still belongs on the API side because the main job is forwarding data and rendering the returned result.

Submit either form and this panel will show the backend-style response that HyperBricks rendered for the user.
Plugin

Action that needs extra decision-making

This side simulates an import action. Before anything is rendered, the code has to validate the input, normalize the tags, decide what the import plan should be, and then hand those values to a template. That is where a plugin is more natural.

Submit the import form and this panel will show the computed plan that the plugin prepared.

How to choose

Choose the API route shape when:
  • the action mostly means “send these fields to the backend”
  • the backend system already owns the save, rename, delete, or fetch logic
  • the response already comes back as data that a template can show directly

Choose a plugin when:
  • the action needs validation, cleanup, or branching before the result is known
  • the action behaves more like a workflow than a plain save
  • one piece of code should own the logic for deciding what happens next

Refresh probe

The API-side action sends a small HTMX event after it finishes. Both mock success and conflict actions send the event. The probe shows event delivery; it does not confirm a save.
