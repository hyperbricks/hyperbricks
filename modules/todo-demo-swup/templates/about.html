How it works

This demo uses HyperBricks and Swup to update your to do list without reloading the page. Your tasks and scratchpad notes are saved in this browser.

Updating your list

  1. When you open the app, it loads your saved tasks from browser storage.
  2. When you add, complete or delete a task, the browser sends the updated list to HyperBricks.
  3. HyperBricks checks the task data and returns HTML for the list and progress counts.
  4. Swup updates the task panel. The browser saves the changes after the update succeeds.

Filters use the same process to show all, active or completed tasks. If an update fails, the changed list is not saved. Use Refresh list to try again.

Using the scratchpad

Use the scratchpad for notes while you work. Notes are saved automatically as you type and restored when you reopen the page. Updating a task leaves the scratchpad in place.

Where your data is stored

Tasks and notes are saved in localStorage, which is part of your browser's site data. They are available in the same browser profile at the same site address. They do not sync to another browser or device, and clearing the site's browser data removes them.

There is no account or database. HyperBricks receives the task list to render each update but does not save it. Task text is sent in the request URL, which may appear in server logs.

You can add up to 20 tasks, with up to 120 characters per task. If browser storage is unavailable, changes cannot be kept after a page reload.

How the demo is built

HyperBricks serves both pages and renders the task list. The browser requests list updates, and Swup displays the returned HTML. The navigation links load a full page.
