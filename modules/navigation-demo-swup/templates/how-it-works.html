FOR DEVELOPERS

How it works

HyperBricks renders the pages. Swup handles navigation between them. This page uses the same setup as the rest of the demo.

What happens when you click a link?

  1. Swup intercepts an internal link and requests the destination page.
  2. HyperBricks returns a complete HTML document, including its section menu.
  3. The current content fades out. Swup replaces the main content and navigation with the matching containers from the response.
  4. The new content fades in, the URL and document title update, and the menu marks the current page.

Open any URL directly or reload it and HyperBricks serves that same complete page. Without JavaScript, the links work as ordinary page navigation.

The section menu comes from the pages

Each page declares a section and an index. HyperBricks builds the menu from that section, sorts it by index, and renders the active link with aria-current="page".

night_owl_cafe_page:
  - inherit: guide_page
  - route: night-owl-cafe
  - title: Night Owl Café
  - section: guide_navigation
  - index: 20

The menu definition lives in hyperbricks/partials/navigation.hyperbricks.yaml. Adding a page to the section adds its navigation link; no JavaScript menu list needs updating.

Content and menus, one page request

const swup = new Swup({
  containers: ["#swup", "#guide-navigation", "#developer-navigation"],
  animationSelector: ".transition-page, .transition-item",
  cache: false
});

#swup contains the page content. #guide-navigation contains the section menu, so its active state arrives with the new page. The surrounding header and footer stay in place.

The separate #developer-navigation section menu places How it works at the top-right of the header, outside the location index. Every route provides all three containers. There is no separate fragment endpoint, JSON API, or client-side HTML renderer. Swup caching is disabled so the next visit picks up development edits.

The animation is CSS

Swup adds classes to the HTML element during navigation and waits for the CSS transitions to finish. This demo uses a 180ms page fade, a 240ms entrance with 8px of vertical movement, and a short stagger on the directory rows.

The animation rules live in resources/css/app.css. No animation plugin is required. A reduced-motion media query and a visit:start hook disable animated visits when the browser reports that preference.

History, focus, and page titles

Swup manages the URL and document title. Back and Forward use its default nonanimated history handling. After a page view, a small hook focuses the new main region without changing the scroll position and announces the page title to screen readers.

The shared assets load once. If you add interactive widgets later, initialise them after a page view and clean them up before their container is replaced.

Where to look in the module

hyperbricks/app.hyperbricks.yaml
Routes, section membership, ordering, and venue content.
hyperbricks/partials/site.hyperbricks.yaml
The shared page definition and asset imports.
templates/shell.html
The persistent layout and replaceable containers.
templates/place.html
One template reused by all four venues.
resources/js/app.js
Swup setup, reduced-motion handling, and focus announcements.
hyperbricks/partials/assets.hyperbricks.yaml
Native esbuild bundling for the local JavaScript and CSS.

Try it yourself

  • Follow a venue link, then use Next stop, Back, and Forward.
  • Reload a venue URL to see the same page served directly.
  • Watch the Network panel: navigation requests HTML documents.
  • Enable reduced motion or disable JavaScript and follow the links again.
  • Add a page with section: guide_navigation and a new index to extend the menu.

For more examples, see the Swup getting started guide, animation demos, and HyperBricks component reference.
