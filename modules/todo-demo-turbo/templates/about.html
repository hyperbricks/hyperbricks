One list. HTML from the server.

This version uses Hotwire Turbo. HyperBricks serves the pages, builds the assets and renders every task-list update.

From a click to an updated list

  1. Your browser reads the tasks from localStorage.
  2. Adding, checking or deleting a task creates a new list in memory.
  3. Hotwire Turbo requests /fragments/tasks with that list.
  4. A HyperBricks template validates the data, calculates progress and returns HTML.
  5. Hotwire Turbo replaces the list panel. After a successful update, the browser saves the tasks.

The scratchpad is outside the updated panel. Type a note there, then change a task: the note stays in place because the page does not reload. It is also saved automatically in localStorage and restored after a full reload.

Storage and scope

Tasks and notes belong to this browser and origin. This module uses separate localStorage keys for its tasks and scratchpad. Another browser profile has a separate list; tabs on the same origin share it. There is no database, login, Go plugin or Goja component.

The render-only GET request carries task data in its URL. HyperBricks does not persist it, but URLs may appear in request logs. The demo is limited to 20 tasks with titles of up to 120 characters. Browser storage can be cleared or unavailable.

This demonstrates Hotwire Turbo fragment updates with HyperBricks, not every feature of the library. Page navigation uses ordinary links.
